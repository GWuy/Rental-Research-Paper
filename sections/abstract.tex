\begin{abstract}
Rental property management crosses several data and process boundaries: property discovery, booking, tenancy, billing, and maintenance. A change in one domain may require updates or notifications in another, while a failed or repeated message can leave the workflow inconsistent. This paper develops a working design for a Java Spring Boot rental platform organized into seven business services. The design combines synchronous service calls for immediate queries with Apache Kafka events for cross-service state changes, and treats database ownership, role-based access control, transactional outbox publication, and idempotent consumption as explicit consistency and security concerns. Because the reviewed literature reports event-driven operational costs and no controlled evaluation of outbox-based consistency on a rental workload, boundaries are derived from the specification and an evaluation protocol is defined rather than an advantage asserted.
