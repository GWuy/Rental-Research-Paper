\begin{abstract}
Rental property management spans property discovery, rental requests, tenancy, billing, and maintenance. A request can be accepted before a downstream contract exists, and message redelivery can repeat a business effect unless the consumer records what it has processed. This paper specifies seven service boundaries and an event-driven acceptance workflow for a Java Spring Boot rental platform. It distinguishes the target architecture from the inspected backend snapshot: the gateway and several service modules contain source code, but Listing and Booking is absent from the parent Maven build and the supplied Docker Compose file does not declare the complete workflow. We define an evaluation protocol for data ownership, authorization, API latency and throughput, event reconciliation, duplicate handling, and recovery after publisher or consumer interruption. These are proposed tests rather than reported experiments; no end-to-end or performance result is claimed.
\end{abstract}
