\begin{abstract}
Rental property management crosses several data and process boundaries: property discovery, booking, tenancy, billing, and maintenance. A change in one domain can require updates or notifications in another, while a failed or repeated message can leave the overall workflow inconsistent. This paper develops a working design for a Java Spring Boot rental platform organized into seven business services. The proposed design combines synchronous service calls for immediate queries with Apache Kafka events for cross-service state changes. It examines database ownership, role-based access control, transactional outbox publication, and idempotent consumption as explicit consistency and security concerns. The paper also defines an evaluation protocol for API latency and throughput, event delivery and duplication, and recovery after service or publisher failures.
