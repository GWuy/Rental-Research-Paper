\begin{abstract}
Rental property management crosses several data and process boundaries: property discovery, booking, tenancy, billing, and maintenance. A change in one domain may require updates or notifications in another, while a failed or repeated message can leave the workflow inconsistent. This paper develops a working design for a Java Spring Boot rental platform organized around seven core business services, with an auxiliary chat service included in the runtime configuration. The design combines synchronous service calls for immediate queries with Apache Kafka events for cross-service state changes, and treats database ownership, role-based access control, transactional outbox publication, and idempotent consumption as explicit consistency and security concerns. The implementation includes source-level integration and Docker Compose configuration for the service topology; however, complete multi-container runtime verification and controlled performance measurements remain pending. Accordingly, an evaluation protocol is defined to measure API latency and throughput distributions, event delivery and duplication, and recovery after service or publisher failure.
\end{abstract}
