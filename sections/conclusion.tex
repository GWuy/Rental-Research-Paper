\section{Conclusion and Future Work}\label{sec:conclusion}

This paper specifies an event-driven design for rental property management and a protocol for evaluating it. The target acceptance workflow links a local transaction in Listing and Booking to draft creation in Contract and Tenant through a Kafka event. The protocol will test whether each committed acceptance yields at least one corresponding publication and exactly one correct draft by a predefined observation cutoff, including under redelivery and selected failures. The supplied backend snapshot does not yet deploy the complete path, so the criterion is a test objective, not an observed result.

The current contribution is a boundary model, a source-to-specification gap audit, and a reproducible evaluation plan. Before empirical submission, the Listing and Booking publisher and the missing Compose services must be integrated, the parallel internal draft endpoint reconciled, and versioned runs with retained evidence must measure API behavior, event outcomes, and recovery. Later work can extend the tested invariant to contract signing and billing, where more services react to the same contract events.
